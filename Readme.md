# Fullstack Dashboard: клиенты и заказы

Дашборд с двумя связанными таблицами: клиенты и заказы. Главная таблица клиентов подгружает данные блоками через Infinite Row Model, таблица заказов фильтруется по выбранному клиенту и поддерживает добавление, изменение и удаление записей.

В качестве шаблона для клиентской части использовался пример с сайта [creative-tim.com](https://demos.creative-tim.com/material-dashboard-material-ui-v4/#/admin/table). В качестве шаблонной таблицы выбран вариант **Simple Table**.

## Возможности

- Таблица «Клиенты» на AG Grid с infinite loading. Данные подгружаются блоками по 30 строк через `limit` и `offset` на сервере.
- Таблица «Заказы» с фильтрацией по выбранному клиенту.
- Кнопки «Добавить запись», «Изменить», «Удалить». Две последние активны только при выбранной строке, удаление требует подтверждения.
- Модальная форма заказа. Клиент выбирается из выпадающего списка, это реализуется через связь по внешнему ключу.
- Валидация на клиенте и на сервере, уведомления об успехе и ошибках, индикатор загрузки, пустое состояние, сообщение при недоступности сервера.
- Боковое меню с тремя пунктами: «Клиенты и заказы», «Обзор», «Настройки».
- REST API с CRUD для клиентов и заказов.

## Быстрый старт

Все типовые сценарии собраны в `run.ps1` (Windows) и `run.sh` (Linux/macOS, не забудьте дать права на выполнение `chmod +x run.sh`):

| Команда       | Действие                                              |
| ------------- | ----------------------------------------------------- |
| `run up`      | Prod-контур Docker, наружу только клиент на nginx     |
| `run dev`     | Клиент через Vite + опубликованные порты 5432 и 5000  |
| `run rebuild` | Пересоздание БД с нуля по `init-db.sql`               |
| `run down`    | Остановка контейнеров                                 |
| `run logs`    | Логи сервисов                                         |
| `run status`  | Состояние контейнеров                                 |
| `run local`   | БД в Docker, сервер и клиент локально (`npm run dev`) |

Пример: `.\run.ps1 dev` или `./run.sh dev`.

## Запуск локально

### 1. База данных

Убедитесь, что PostgreSQL запущен, затем выполните скрипт от имени пользователя с правом создавать базы:

```bash
psql -U dashboard_owner -f init-db.sql
```

Скрипт создаёт базу `dashboard_db`, таблицы `clients` и `orders`, индекс на `orders.client_id` и тестовые данные: 150 клиентов и 300 заказов. Скрипт можно запускать повторно, таблицы пересоздаются.

Файл использует метакоманды psql, поэтому выполнять его нужно именно через `psql`.

### 2. Сервер

```bash
cd server
cp .env.example .env
npm ci
npm run dev
```

Заполните `server/.env`:

| Переменная    | Описание                                 | Пример                  |
| ------------- | ---------------------------------------- | ----------------------- |
| `PORT`        | Порт сервера                             | `5000`                  |
| `DB_HOST`     | Хост базы                                | `localhost`             |
| `DB_PORT`     | Порт базы                                | `5432`                  |
| `DB_NAME`     | Имя базы                                 | `dashboard_db`          |
| `DB_USER`     | Пользователь базы                        | `postgres`              |
| `DB_PASSWORD` | Пароль пользователя                      | задайте свой            |
| `CORS_ORIGIN` | Разрешённые адреса клиента через запятую | `http://localhost:5173` |

Проверка: `http://localhost:5000/api/health` должен вернуть `{"status":"ok"}`.

Для запуска без режима отслеживания изменений используйте `npm start`.

### 3. Клиент

```bash
cd client
npm ci
npm run dev
```

Заполните `client/.env`:

| Переменная              | Описание                      | Пример                  |
| ----------------------- | ----------------------------- | ----------------------- |
| `VITE_API_URL`          | Базовый путь к API            | `/api`                  |
| `VITE_API_PROXY_TARGET` | Адрес сервера для прокси Vite | `http://localhost:5000` |

Приложение откроется на `http://localhost:5173`. Запросы на `/api` проксируются на `http://localhost:5000`, настройка лежит в `client/vite.config.js`.

Базовый адрес API можно переопределить переменной `VITE_API_URL`, по умолчанию используется `/api`.

## Запуск через Docker Compose

```bash
cp .env.example .env
```

Задайте в `.env` значение `POSTGRES_PASSWORD`, затем:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Приложение будет доступно на `http://localhost`, порт меняется переменной `CLIENT_PORT`. База инициализируется скриптом `init-db.sql` при первом запуске. Чтобы пересоздать данные, удалите том:

```bash
docker compose down -v
```

Для разработки с открытыми портами базы и сервера:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

## API

Базовый адрес: `/api`. Все ответы в формате JSON.

### Клиенты

| Метод  | Маршрут                                   | Описание                                                                                                                                 |
| ------ | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/clients?limit=&offset=`             | Страница клиентов, ответ вида `{ "data": [...], "total": 150 }`.                                                                         |
| GET    | `/api/clients/all?search=&limit=&offset=` | Список `id` и `full_name` для выпадающего списка, ответ вида `{ "data": [...], "total": 150 }`. Поиск по имени и пагинация необязательны |
| GET    | `/api/clients/:id`                        | Один клиент                                                                                                                              |
| POST   | `/api/clients`                            | Создание                                                                                                                                 |
| PUT    | `/api/clients/:id`                        | Изменение                                                                                                                                |
| DELETE | `/api/clients/:id`                        | Удаление, заказы клиента удаляются каскадно                                                                                              |

### Заказы

| Метод  | Маршрут                 | Описание                                       |
| ------ | ----------------------- | ---------------------------------------------- |
| GET    | `/api/orders?clientId=` | Список заказов, фильтр по клиенту необязателен |
| GET    | `/api/orders/:id`       | Один заказ                                     |
| POST   | `/api/orders`           | Создание                                       |
| PUT    | `/api/orders/:id`       | Изменение                                      |
| DELETE | `/api/orders/:id`       | Удаление                                       |

### Служебные

| Метод | Маршрут       | Описание                |
| ----- | ------------- | ----------------------- |
| GET   | `/api/health` | Проверка работы сервера |

### Тело запроса для заказа

```json
{
  "client_id": 1,
  "title": "Заказ #1",
  "order_date": "2025-01-15",
  "quantity": 2,
  "amount": 1500.5
}
```

### Коды ответов

| Код | Когда                                               |
| --- | --------------------------------------------------- |
| 200 | Успешное чтение или изменение                       |
| 201 | Запись создана                                      |
| 204 | Запись удалена                                      |
| 400 | Неверные данные, неверный id, несуществующий клиент |
| 404 | Запись или маршрут не найдены                       |
| 500 | Внутренняя ошибка сервера                           |

## Схема базы данных

**clients**: `id`, `full_name`, `city`, `birth_date`, `loyalty_points`, `discount`

**orders**: `id`, `client_id` со ссылкой на `clients.id` и каскадным удалением, `title`, `order_date`, `quantity`, `amount`
